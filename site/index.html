How it works

中央只分发 SETI 复核任务和收结果，模型调用发生在志愿者本机

路线 A：BYOK API Worker

志愿者在本机配置自己的 OpenAI、Anthropic 或本地模型环境。 Worker 领取任务、调用模型、生成结构化结果。API Key 不离开本机。

路线 B：Agent Client

Codex / Claude Code 用户打开仓库，按 AGENTS.md 领取任务。 用户能审查每一步，最后决定是否提交结果。

可审计科学输出

结果必须包含证据、置信度、限制和推荐动作。LLM 不直接宣布发现， 只辅助整理、解释、复核和排序。

Run locally

一分钟跑通 SETI 复核 Demo

当前原型包含 SETI 候选信号复核与 TESS-SPOC transit 复核两个任务 fixture、 dry-run worker、本地协调服务、task/result schema 校验、任务准入评分、 任务 manifest 校验、结果聚合摘要和敏感信息扫描。

Project health

公开状态优先看可验证路径，而不是宣传口号

CI / Pages GitHub Actions 持续验证测试和静态站点部署。 推送 main 后必须确认 CI 与 Pages 成功。 Release gate 发布前按 release readiness checklist 走 fresh-clone 检查。 本地测试、coordinator smoke、leaderboard、task summary 和 Actions 都要过。 Task intake 新任务必须有公开来源、许可、caveats 和准入评分。 任务先过 intake checker 和 manifest 校验，再进入 worker 或 agent-client 流程。 Roadmap 当前重点是可运行原型、任务准入和志愿者信心。 后续网络协调能力等安全边界更清楚后再扩展。

Safety boundary

不是共享账号，也不是集中 token 池

  • 不上传 API Key、OAuth Token、Cookie、Session ID。
  • 不代理 ChatGPT / Claude 网页订阅，不转售额度。
  • 结果提交前做 schema 校验和敏感信息扫描。
  • 所有 demo 输出都需要人工科学复核，不能当作发现声明。
